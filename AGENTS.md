# Project Yasmina — Core Instructions & Agent Guidelines

## 1. Project Identity & Scope
**Project Yasmina** is an enterprise-grade, AI-orchestrated B2B trading, sourcing, and public/private tender bidding engine tailored for the German cleaning and hygiene supplies sector (paper towels, nitrile/latex gloves, garbage and waste bags across all thicknesses, volumes, and color standards).

## 2. Mandatory Architecture & References
- **Master Engineering Specification:** You **MUST** read and strictly follow all definitions, Enums, Pydantic schemas, SQL filters, pricing rules, and compliance requirements defined in **`docs/DETAILED_SPEC.md`**.
- **Isolation of External Services:** Do **NOT** clone external ERP or automation repos. External systems (`ERPNext`, `n8n`, `PostgreSQL/pgvector`, `MinIO`) run as isolated Docker containers (`docker-compose.yml`) and communicate solely via REST APIs, signed Webhooks, or SQL connections.
- **Strict Separation of AI vs. Deterministic Logic:** LLMs (DeepSeek via OpenAI-compatible `ChatOpenAI`) are restricted to extraction, matching assistance, and summarization. All financial calculations, margins, tiered volume discounts, MOQ rounding, and VAT math must be executed by the 100% deterministic Python pricing engine (`src/services/pricing_service.py`) using `decimal.Decimal`.
- **Pre-Validation Normalization:** Raw extracted German strings (e.g., `"Nitril"`, `"Gr. 8"`, `"blau"`) must pass through `src/parsers/normalizers.py` to map into strict Pydantic Enums **before** schema validation.
- **Human-in-the-Loop (HITL) Governance:** No ERPNext Quotation creation or GAEB `.x84` bid export may execute without a valid Ed25519 cryptographic human approval signature (`CustomerOffer.ed25519_approval_signature`).

## 3. Tech Stack & Key Libraries
- **Language:** Python 3.11+ / FastAPI / Pydantic v2 (`strict=True`, `extra="forbid"`).
- **Parsers:** `pygaeb` (`.x83`, `.d83`, `.x84`), `Docling` (PDF tables).
- **Database & Search:** SQLAlchemy 2.0 Async, `asyncpg`, Alembic migrations, `pgvector` (HNSW index).
- **Workflow & AI:** LangGraph, PostgreSQL SQLAlchemy checkpoint saver, `langchain-openai` (DeepSeek-Chat / DeepSeek-Reasoner).
- **E-Invoicing:** `factur-x` (ZUGFeRD 2.2), custom XRechnung 3.0 / EN 16931 UBL generator, official KoSIT CIUS Schematron via `saxonche`, branded PDF/A-3 carrier invoice.
- **Identity & Security:** Argon2id password hashing, short-lived JWT access tokens with `jti`, rotating hashed refresh-token families, PostgreSQL JTI blocklist, four-eyes approval and Redis-backed token-bucket rate limits (in-process fallback without Redis).

## 5. Execution Protocol for Coding Agents
When given an implementation task:
1. **Read `docs/DETAILED_SPEC.md`** relevant to the task section first.
2. Implement code adhering strictly to the typed schemas, naming conventions, and decimal precision rules.
3. Verify that unit tests pass and that strict mode validation does not encounter un-normalized string errors.

## 6. Build, Run & Verification Commands
- Setup: `python -m pip install -e ".[dev,parsing,ai,e-invoicing]"`; `.env` is created from `.env.example` on first preflight/API start (copy it manually for other tooling).
- Web guidance skill: `.agents/skills/modern-web-guidance/` (pinned by `skills-lock.json`) is the mandatory first lookup for HTML/CSS/client-side JS work in `frontend/`; refresh with `npx modern-web-guidance@latest install --agent universal -y`. Never hand-roll patterns from memory for dialogs, forms, accessibility, CWV or CSS layout.
- Tests: `python -m pytest -q` (config lives in `pyproject.toml`); live DB tests use `YASMINA_TEST_DATABASE_URL`.
- E2E: seed with `python scripts/seed_e2e.py --suffix local --output frontend/tests/e2e/.fixtures.json` against a migrated database, run the API on `127.0.0.1:8000` with `ED25519_APPROVAL_PRIVATE_KEY`, `COMPANY_*`, `N8N_WEBHOOK_BASE_URL=http://127.0.0.1:5678`, `N8N_WEBHOOK_HMAC_SECRET=e2e-n8n-secret`, `N8N_CALLBACK_URL=http://127.0.0.1:8000/api/v1/integrations/n8n/supplier-quotes` and `N8N_DISPATCH_PENDING_TTL_SECONDS=2`, then `cd frontend && npm run test:e2e`; Playwright also starts `frontend/tests/e2e/mock-n8n-server.mjs`, which verifies the outbound HMAC and signs a supplier-quote callback. The CI `e2e` job provisions PostgreSQL/MinIO/ClamAV, migrations, fixtures, uvicorn, Vite and the mock relay. `operations.spec.ts` covers the admin Workers & Ingestion flow and Sales/Approver denial; the seed adds a quarantine tender, a failed quarantine job, a dead-letter job and a succeeded worker run.
- Dashboard: `cd frontend && npm install && npm run dev` (Vite on 5173, `/api` proxied to `127.0.0.1:8000`); quality via `npm run lint` and `npm run build` (strict TypeScript). Views: overview (`/ops/summary`, `/ops/activity`, `/ops/outbox-status`), offers workspace (`/offers` with status/owner filters, detail panel, the server-signed four-eyes approval dialog and its optional e-invoice section that appends an `invoice` payload for ZUGFeRD/XRechnung, deep-linked from the outbox), outbox console (`/ops/outbox` list + retry), admin-only Workers & Ingestion console (`/ops/workers` with worker-run history, queue health, quarantine/dead-letter tables, retry/discard confirmations and a read-only portal probe), tender board/detail (`GET /tenders[/{id}]`, GAEB/PDF upload with ClamAV/parser feedback, parsed-position review, admin owner assignment, supplier-quote comparison and manual entry, RFQ dispatch, source download, matching, linked offers, server-priced offer creation from persisted quotes or manual costs with margin/freight/pallet controls, and approved `.x84` bid download), invoices (responsive table, detail sheet with totals/VAT/line items/documents, credit-note history and documents, cancel/email/credit-note dialogs, GoBD hash-chain timeline), public `/forgot-password` + `/reset-password`, admin catalogue overrides (`GET/POST /admin/catalog/overrides`), account security (`/settings` password change, sign-out-everywhere, TOTP enrolment with QR/manual key and one-time recovery codes, recovery-code login) and admin users (`/admin/users` create, roles, reset token, lock/unlock). Set `VITE_API_BASE_URL` for separate hosting, add the origin to backend `CORS_ALLOWED_ORIGINS`, and keep the hosts same-site because refresh uses an HttpOnly `SameSite=Strict` cookie.
- Quality: `python -m ruff check .`, `python -m ruff format --check .`, `python -m mypy src`.
- Catalogue: `python -m src.admin seed-catalog --file catalog.csv [--embedding-provider auto|local|hashing] [--dry-run] [--ignore-manual-overrides]`; re-imports merge by `(supplier, article_number)`, preserve pinned `catalog_articles.manual_overrides`, never clear omitted fields and collapse duplicate rows (last wins).
- Catalogue reindex: `python -m src.admin reindex-catalog [--batch-size N] [--only-missing] [--respect-overrides] [--dry-run] [--json] [--embedding-provider …] [--allow-hash-embeddings]`; recomputes pgvector embeddings in place, never deletes rows, commits per page and audits `SYSTEM_CATALOG_REINDEXED`.
- Embeddings: seeding/reindex share `src/services/embedding_pipeline.py` (batch size `EMBEDDING_BATCH_SIZE`, retries `EMBEDDING_MAX_RETRIES` with exponential backoff honouring `Retry-After` for 429/5xx, progress on stderr so `--json` stdout stays clean).
- Extraction eval: `python -m pytest -q tests/evals/test_extraction_eval.py -s` (live accuracy gate when `DEEPSEEK_API_KEY` is set).
- API: `python -m uvicorn src.main:app --host 127.0.0.1 --port 8000 --reload` (startup runs preflight).
- Infrastructure: `docker compose up -d postgres minio clamav` (add `--profile automation` for n8n).
- Preflight: `python -m src.preflight` (or `python -m src.preflight --json`).
- Approval: the API signs server-side with `ED25519_APPROVAL_PRIVATE_KEY` for the authenticated approver (four-eyes enforced) and the dashboard exposes the approval console at `/offers` (optionally issuing the ZUGFeRD/XRechnung invoice in the same request); approvers can read offers (GET /offers, GET /offers/{id}) while pure sales users stay owner-scoped; `yasmina-approval sign|verify` remains for offline tooling, and `python -m src.admin generate-approval-key` mints a pair (see `src/services/approval_service.py`).
- Auth: `POST /api/v1/auth/token` (returns only the access token; the rotating refresh token is set as an HttpOnly, SameSite=Strict cookie scoped to `REFRESH_COOKIE_PATH`, with `totp_code` or a single-use `recovery_code` when MFA is enabled), `/auth/refresh` (rotates the cookie; a body token remains a fallback for non-browser clients), `/auth/logout` (clears the cookie and blocklists the JTI), `/auth/users` (admin list/create), `PATCH /auth/users/{username}/roles`, `POST /auth/users/{username}/lock|unlock` (self-change/self-lock rejected). Four-eyes rejects self-approval by owner/tender creator.
- Account lifecycle: `POST /auth/password/change` (current password required), `/auth/password/reset` (single-use token), `/auth/password/reset/request` (public, always 202; SMTP delivery to the account e-mail, Telegram fallback), `/auth/users/{username}/password/reset` (admin-issued token), `/auth/logout/all` (revoke every refresh session). Dashboard: `/forgot-password`, `/reset-password`, password change and “sign out everywhere” in `/settings`.
- MFA: `/auth/mfa/setup` returns a base32 secret + `otpauth://` URI, `/auth/mfa/verify` enables TOTP enrollment and returns ten one-time recovery codes, `/auth/mfa/disable` needs password + live code; secrets are Fernet-sealed from `APP_SECRET_KEY`, `users.mfa_last_step` blocks code replay, and `mfa_recovery_codes` stores only SHA-256 hashes. RFC 6238 code lives in `src/services/mfa_service.py`.
- Token retention: `python -m src.admin purge-auth-tokens [--retention-days N] [--dry-run] [--json]` purges expired refresh tokens, stale revoked sessions, expired JTIs and used/expired reset tokens, and appends a `SYSTEM_TOKEN_CLEANUP` audit entry.
- Auth audit: `AuditService` records `USER_LOGIN_SUCCEEDED|FAILED`, `USER_LOGOUT`, `USER_LOGGED_OUT_ALL_DEVICES`, `USER_CREATED`, `USER_PASSWORD_CHANGED`, `USER_PASSWORD_RESET_REQUESTED|COMPLETED`, `USER_MFA_ENABLED|DISABLED`, `USER_MFA_RECOVERY_CODE_USED`, `USER_ROLES_CHANGED`, `USER_LOCKED|UNLOCKED`; never include passwords, reset tokens, recovery codes or TOTP secrets.
- Rate limits: `/auth` 20/min, `/upload` 30/min, other `/api/v1` 300/min by default; adjust `RATE_LIMIT_*` settings. With `REDIS_URL` set (production), an atomic Redis Lua token bucket is shared across replicas; `TRUST_PROXY_HEADERS=true` makes the limiter and access logs use `X-Forwarded-For`/`X-Real-IP` (enable only behind a proxy that overwrites them). `RATE_LIMIT_FAIL_OPEN` controls Redis-outage behaviour.
- Security scanning: `python -m bandit -r src -c pyproject.toml -ll` (medium/high gate) and Trivy against the built image (`aquasecurity/trivy-action` in CI, `ghcr.io/aquasecurity/trivy` locally); the runtime image removes pip/setuptools/wheel.
- Load tests: `pip install -e ".[performance]"` then `locust -f tests/performance/locustfile.py --host http://127.0.0.1:8000 --users 50 --spawn-rate 5 --run-time 5m`; set `YASMINA_LOAD_USERNAME`, `YASMINA_LOAD_PASSWORD`, `YASMINA_LOAD_TENDER_ID`. See `tests/performance/README.md`.
- Observability: `LOG_FORMAT=json` emits structured JSON (request id, method, route, status, duration); `GET /metrics` exposes `yasmina_http_*` and `yasmina_workflow_*` Prometheus metrics; middlewares live in `src/api/observability.py` and `src/api/metrics.py`.
- Production image: `docker build -t yasmina-api:prod .` (multi-stage, non-root UID 10001, precompiled bytecode); `docker build --build-arg INSTALL_EXTRAS="ai,e-invoicing" -t yasmina-api:slim .` skips Docling/pyGAEB.
- Production stack: `cp .env.prod.example .env.prod` then `docker compose --env-file .env.prod -f docker-compose.prod.yml up --build`; add `--profile backup` for the daily encrypted-backup sidecar. Caddy serves `https://localhost` with `tls internal`, builds the SPA via `Dockerfile.frontend`, proxies `/api/*`, `/docs*` and `/openapi.json` to `yasmina-api:8000`, and applies HSTS/frame/nosniff headers. Accept the local CA once (or import `caddy:/data/caddy/pki/authorities/local/root.crt`); API on loopback:8000, services on the internal `backend` network.
- Staging deploy: push to `main` (after green `ci.yml`) or run **Deploy staging** manually; the workflow builds SHA-tagged GHCR images (`yasmina-api`/`-worker`/`-sync-worker`/`-edge`), copies `docker-compose.staging.yml` + scripts to `STAGING_DEPLOY_DIR`, then `scripts/deploy_staging.sh` logs in to GHCR, writes `backups/pre-<tag>-*.sql.gz` via `pg_dump`, runs `alembic upgrade head`, restarts Compose, and calls `scripts/smoke_test.sh` (`/healthz` + authenticated `/auth/me`); smoke failure restores the previous `.deployed_tag` image. `Caddyfile.staging` serves `https://staging.yasmina.bayerclean.net` with automatic Let's Encrypt and `404` for `/docs*`/`/openapi.json`/`/redoc*`; VPS secrets are listed in the README table and `deploy/staging.env.example`.
- Backups: `python -m src.admin generate-backup-key` writes `BACKUP_ENCRYPTION_KEY`; `python -m src.admin backup-postgres [--dry-run] [--retention-days N] [--json]` runs Fernet-encrypted `pg_dump` uploads to `BACKUP_BUCKET` and appends `SYSTEM_BACKUP_COMPLETED`.
- E-invoicing: `XRechnungGenerator` runs KoSIT EN16931 + XRechnung CIUS Schematron via `saxonche`; `ZUGFeRDGenerator` embeds CII XML in the branded PDF/A-3 carrier; `InvoiceRepository` owns gapless `INV-YYYY-XXXX` numbering and multi-rate VAT rows.
- Commercial intake: `POST /tenders/upload` (ClamAV scan + GAEB/PDF parse), `PATCH /tenders/{id}/owner` (admin reassignment), `GET/POST /supplier-quotes` (comparison and manual quote entry), `POST /tenders/{id}/price` (authoritative preview) and `POST /tenders/{id}/workflow` (draft offer) are exercised by the dashboard tender workspace; `POST /integrations/rfq/dispatch` is wired to the RFQ dialog with a stable idempotency key. `POST /offers/{id}/x84` generates an approved offer's GAEB bid from the stored source, persists `gaeb_export_path` and streams it; `GET /offers/{id}/x84` serves the existing export.
- Billing: `GET /api/v1/invoices[/{id}]` (owner-scoped for sales), `POST /invoices/{id}/payments`, `POST /invoices/{id}/credits`, `POST /invoices/{id}/cancel` and `POST /invoices/{id}/email` (admin-only); `CreditNoteRepository` allocates a gapless `GS-YYYY-XXXX` credit number across the invoice VAT buckets and applies it atomically; credit notes get ZUGFeRD/XRechnung type-381 documents under `credit-notes/`. `PricingService.price_offer` adds deterministic flat freight and per-pallet surcharges (zero-margin `FREIGHT`/`PALLET` lines) to net, VAT and gross totals; the invoice detail returns its line items. Email delivery appends an `EMAIL_SENT` GoBD event only after SMTP success.
- GoBD event log: `InvoiceEventRepository` appends hash-chained `invoice_events` for issuance/payment/credit/status changes; PostgreSQL triggers block UPDATE/DELETE/TRUNCATE, and `verify_chain()` re-derives every hash.
- PDF/A-3 gate: `python scripts/generate_sample_invoice.py sample-invoice.pdf` then `docker run --rm -v "$PWD:/data" verapdf/cli:latest -f 3b /data/sample-invoice.pdf`; the report must contain `isCompliant="true"`. The carrier embeds DejaVu TrueType faces from `src/generators/fonts/`.
- Scrape worker: `python -m src.worker scrape|schedule --portal <id|all>`; `python -m src.worker probe --portal <id> [--max-pages N] [--json]` dry-runs one portal read-only (no DB/MinIO/outbox writes, no ingestion jobs) and reports discovered-vs-parsed notices, extraction issues and a zero-result warning (exit 2). Targets/engines/APIs are configured in `config/portals.yaml` (120 targets, only verified ones enabled), with bounded concurrency, per-domain Redis locks/spacing, JSON/XML/TED API preference and cross-portal `dedup_hash` (title + client + deadline). Daily cron via `SCRAPER_SCHEDULE_CRON`.
- Ingestion worker: `python -m src.worker process [--limit N] [--interval SECONDS]` drains `tender_ingestion_jobs` through ClamAV (fail-closed; malware quarantines the job and writes `SYSTEM_SECURITY_ALERT`) before DeepSeek triage/Docling/GAEB parsing, then drains `quotation_sync_jobs` to ERPNext with exponential backoff.
- Catalogue overrides: `GET/POST /api/v1/admin/catalog/overrides` (admin only) list, pin (`add`/`replace`) and clear `catalog_articles.manual_overrides`; identical semantics remain available through `seed-catalog --ignore-manual-overrides` and the repository methods.
- Outbox operations: `GET /api/v1/ops/outbox` (admin/approver/viewer) pages `quotation_sync_jobs` with `last_error`; `POST /api/v1/ops/outbox/{job_id}/retry` (admin/approver) resets a failed job to pending with 0 attempts and audits `SYSTEM_OUTBOX_RETRIED`; `GET /api/v1/ops/outbox-status` returns counts for the dashboard widget. The sync worker sends one Telegram alert per exhausted job (`TELEGRAM_CHAT_ID`, falling back to `TELEGRAM_APPROVAL_CHAT_ID`). n8n RFQ reservations left `pending` past `N8N_DISPATCH_PENDING_TTL_SECONDS` are reclaimed on matching retry and by `python -m src.admin reclaim-dispatch-reservations [--ttl-seconds N] [--dry-run] [--json]`.
- Worker operations: portal locks use `pg_try_advisory_lock`; per-domain locks/spacing use Redis (`yasmina:scrape:domain*`); SIGINT/SIGTERM finish in-flight work; `GET /healthz/worker` exposes `worker_runs` history and outbox counts; Telegram alerts use `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` (falls back to `TELEGRAM_APPROVAL_CHAT_ID`). The daily scheduler first marks past-due invoices `OVERDUE` (`python -m src.worker overdue` for a one-off run). Admin-only ingestion operations: `GET /ops/worker-runs`, `GET /ops/ingestion` (`status`, `quarantined`, `limit`, `offset`), `POST /ops/ingestion/{job_id}/retry`, `POST /ops/ingestion/{job_id}/discard` (audits `SYSTEM_INGESTION_RETRIED`/`SYSTEM_INGESTION_DISCARDED`), `GET /ops/portals` and read-only `POST /ops/portals/{portal_id}/probe` (audits `SYSTEM_PORTAL_PROBED`; never writes ingestion jobs). Quarantine means `status=failed` with a `SECURITY:` `last_error`; retry clears locks/errors and resets attempts, discard terminally marks the job `skipped`.
- Migrations: `python -m alembic upgrade head`; offline SQL preview: `python -m alembic upgrade head --sql`.
